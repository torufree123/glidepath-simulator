# グライドパス・シミュレーター

ターゲットイヤーファンド(TYF/TDF)のグライドパス設計をモンテカルロ・シミュレーションで定量評価するツールです。
`glidepath_simulator_spec_v0.1.md`(仕様書 v0.1)のリファレンス実装として、計算仕様(6章)・機能要件(5章)・コンプライアンス要件(10章)に準拠しています。

## クイックスタート

```bash
npm install
npm run dev        # 開発サーバ(既定 http://localhost:5173)
npm run build      # 型チェック + 本番ビルド(dist/)
npm run preview    # ビルド成果物の確認(既定 http://localhost:4173)
npm test           # エンジン検証テスト一式(6.7 受け入れ基準を含む・41+テスト)
```

起動すると既定条件(30歳→ターゲット60歳→95歳、標準型グライドパス、iDeCo想定拠出)で自動的に概算プレビュー(2,000パス)が実行されます。入力を変更すると自動で再計算され、ヘッダーの「本計算を実行」で設定パス数(既定10,000)の確定計算を行います。

## 画面構成

| 比較(CRN) | 最大5設定を同一乱数系列で並列比較。指標差分テーブル+グライドパス/中央値経路の重ね合わせ | UC-01/03/06, FR-CMP-01, FR-OUT-07 |
| 感応度 | w_start / w_end / 逓減開始年齢 / 拠出額 / 信託報酬 の±変化に対する成功確率のトルネードチャート | FR-CMP-02 |
| 前提・設定 | CMAセット管理(正定値検証つき相関行列エディタ)、拠出上限マスタ、精度検証(6.7)、実行履歴(append-only)、ガードレール対応表 | FR-CMA, FR-CF-02, 8章, CP-06 |

すべてのチャートに「表」ビュー(アクセシブルな数値テーブル)とホバー・ツールチップが付属します。「レポート」ボタンから前提条件・免責・再現情報(engine_version / cma_version / seed / run_id / result_hash)を含む印刷用レポート(ブラウザ印刷→PDF保存)を出力できます(FR-REP-01/02)。

## 計算仕様の実装(6章)

- **リターン生成**: 多変量対数正規。月次対数リターン ℓ = m + S·L·z(m=ln(1+g)/12、S=diag(σ/√12)、L=chol(P))。算術リターン入力には g=(1+μ)·exp(−σ²/2)−1 の変換を適用し、適用の事実を前提条件に記録。
- **再帰式**: 積立期 V′=(V+C)(1+R)κ−F、取り崩し期 V′=max(0,V−W)(1+R)κ−F。κ=(1−f)^(1/12)。枯渇パスは以後0固定で枯渇月を記録。
- **取り崩し**: 定額名目 / 定額実質(インフレ連動)/ 定率 / 期間指定(残存月数均等)。簡易課税モードでは希望受取額を確保するグロスアップ(取得原価を按分減額)。
- **CRN**: 比較・感応度は全バリアントで同一の乱数系列(生成した資産クラスリターン)を共有。
- **指標**: 成功確率(+MC標準誤差 √(p(1−p)/N))、期待SF、CVaR5%、パーセンタイル系列(5/25/50/75/95・月次)、最大DD分布、ターゲット直前5年下落分布、年齢別枯渇確率、資産寿命、SoRRストレス差分。

### 精度検証(6.7)とゴールデンシード

`npm test` で解析解突合を自動検証します(設定タブからブラウザ内でも実行可能)。

- N=10,000・30年・単一資産で、中央値誤差 < 0.5%、5/25/75/95分位誤差 < 1.5%。
- N=10,000 では分位点のMC標準誤差(p05で約2%)が許容値を上回るため、仕様11章の「固定シードのゴールデンラン」として **GOLDEN_SEED=159**(全基準を余裕43%以下でクリア)に対する決定論的検証を採用しています。
- 不偏性は N=100,000 で誤差が理論どおり 1/√10 に縮小すること(全ケース≦0.46%)を別テストで検証しています。

## 仕様からの逸脱・簡略化(要レビュー事項)

| 項目 | 仕様 | 本実装 | 理由・備考 |
|---|---|---|---|
| 乱数生成器 | PCG64(FR-SIM-02) | PCG32(XSH-RR、64bit状態)。BigInt参照実装との完全一致をテストで保証 | ブラウザでのBigInt演算が性能要件(10,000×840ヶ月を3秒以内)を満たさないため。(engine_version, seed) での完全再現性は保証 |
| 計算層の言語 | Python/NumPy(4章) | TypeScript(Web Worker)。エンジンはUI非依存モジュールでNode単体実行(vitest)も可能 | 単体で動作する配布物とするため。REST/MCP化する際は同一スキーマでPython移植または本エンジンをそのまま利用 |
| REST API / MCPツール(7章) | simulate / compare 等 | 未実装。Workerメッセージが同一の入出力スキーマ(SimulationRequest/Result)を実装 | Phase 1 スコープ。スキーマは仕様7.3準拠 |
| LLM説明層(FR-EXP) | LLMによる文章生成 | 決定論的テンプレート(数値はエンジン出力の差し込みのみ)+禁止辞書ガードレール+定型文フォールバック | FR-EXP-01の契約(数値の生成・改変禁止)を最も強い形で満たす。LLM接続時も同じ検査・フォールバックを通す設計 |
| レポート | PDF/PPTX(FR-REP-01) | 印刷用ビュー(ブラウザ印刷→PDF)。PPTX未対応 | 前提・免責・再現情報の自動掲載(FR-REP-02)は実装済み |
| SimulationRun(8章) | append-only DB | localStorage への追記保存(直近50件、params+seed+SHA-256ハッシュ) | 監査要件の本実装はサーバ側の責務 |
| 死亡率加重(FR-CF-05)/ ブートストラップ等(FR-SIM-07)/ 準最適化(FR-CMP-03)/ 確率的インフレ | Phase 2 | 未実装 | 仕様どおり Phase 2 |
| 賞与月 | 暦月 | 開始月起点の年内月番号(1〜12)として扱う | 開始暦月の入力を持たないため。UIに明記 |

## コンプライアンス実装(10章)

- **CP-01/02(断定・推奨表現の遮断)**: 禁止辞書(必ず/確実/保証/元本保証/推奨/おすすめ/〜すべき 等)+検査で説明文を遮断し定型文へフォールバック。免責の否定形(「保証するものではありません」)は許容。
- **CP-03(中立表示)**: 比較は追加順で表示し、優劣バッジ・推奨表示を持たない。感応度の並びは影響度順である旨を明記。
- **CP-04(免責常時表示)**: 全画面フッター・前提条件タブ・レポートに DSC-001 を表示。
- **CP-05(前提の透明性)**: CMA出所・作成日・リターン種別(算術/幾何)と変換記録・手数料・税・インフレを前提条件パネルとレポートに常時掲載。
- **CP-06(ガードレール対応表)**: 設定タブ「このツールについて」に G0〜G4 対応表を掲載。

## UIデザイン

チャートは検証済みのカテゴリカルパレット(隣接ペアのCVD分離 ΔE≥8)を固定順で使用し、凡例・直接ラベル・表ビュー・クロスヘアツールチップを全チャートに備えます(単一系列+不確実性帯のファンチャートは同一ヒューの濃淡、感応度はダイバージング blue↔red)。数表・軸は等幅数字(tabular-nums)、大きなKPI値はプロポーショナル数字。ライトテーマのみ(印刷前提)。
